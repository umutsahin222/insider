## Confirmed findings

### CONTRACT-1 · low · `api/openapi.yaml:304`
- **Rule:** CLAUDE.md, "`api/openapi.yaml` is the contract".
- **Evidence:** `POST /v1/templates` runs under `maxBody(maxSingleBody)` (`internal/httpapi/router.go:154`).
  `decodeJSON` returns `*http.MaxBytesError`, which `errors.go:49-50` maps to `413`. The
  operation documents only 201, 400, 409 and 422. The two other write routes already reference
  the `PayloadTooLarge` response.
- **Failure scenario:** a body over 1 MiB gets a `413` the contract does not describe.
- **Verifier (confidence 9):** confirmed through `templates.go:38-39`, `errors.go:79-81` and the
  existing 413 test for notifications. Lowered to `low`, because a schema-conforming request
  (body `maxLength` 20000) never reaches 1 MiB.

### CONTRACT-4 · low · `api/openapi.yaml:359`
- **Rule:** CLAUDE.md, "`api/openapi.yaml` is the contract".
- **Evidence:** `GET /v1/ws` calls `websocket.Accept` with `OriginPatterns` (`internal/httpapi/ws.go:61`)
  after the 400/404 checks. The spec lists 101, 400 and 404 only.
- **Failure scenario:** a browser from a disallowed origin is rejected with an undocumented
  `403` (text/plain, not problem+json).
- **Verifier (confidence 9):** checked against the coder/websocket v1.8.15 source (`accept.go`).
  - A failed origin check returns `403` via `http.Error`.
  - Missing `Connection`/`Upgrade` headers return `426`.
  - A bad `Sec-WebSocket-Version` or `Sec-WebSocket-Key` returns a text/plain `400`.

  None of these is documented, and `ws_test.go` has no origin test. Lowered to `low`: the
  description mentions `WS_ALLOWED_ORIGINS`, and browsers do not expose handshake codes to page
  scripts.

### CONTRACT-5 · low · `api/openapi.yaml:682`
- **Rule:** CLAUDE.md, "`api/openapi.yaml` is the contract".
- **Evidence:** the `Notification` schema leaves out of `required` the fields `batch_id`,
  `idempotency_key`, `template_id`, `scheduled_at`, `last_error`, `provider_message_id`,
  `correlation_id` and `sent_at`. `notificationResponse` (`internal/httpapi/dto.go:65-85`) always
  emits them, as `null` when unset. The same holds for:
  - `DeliveryAttempt` `status_code` and `error`;
  - `BatchSummary` `counts` (all five statuses);
  - `Stats` `by_priority` (all three priorities).
- **Failure scenario:** generated clients type always-present fields as optional.
- **Verifier (confidence 8):** confirmed. The spec is inconsistent, since `StatusEvent` *does*
  list its nullable fields as required. One correction: `Health.checks` must stay optional,
  because `/healthz` omits it.

### CONTRACT-6 · low · `api/openapi.yaml:67`
- **Rule:** CLAUDE.md, "`api/openapi.yaml` is the contract".
- **Evidence:** the correlation middleware (`internal/httpapi/middleware.go:22-32`) replaces
  any `X-Correlation-ID` that does not match `^[A-Za-z0-9._:-]{1,128}$` with a fresh UUID and
  always sets the response header. The `CorrelationID` parameter says only `maxLength: 128`, and
  no response declares the header.
- **Failure scenario:** a client sending `abc def` gets a different ID back, and the contract
  does not say why.
- **Verifier (confidence 8):** confirmed; `TestCorrelationID` pins the replacement. The "cannot
  discover the header" half is overstated, because the info text mentions the echo. The real
  defect is the missing pattern.

### CLAIM-1 · low · `README.md:384`
- **Rule:** documentation must match the code.
- **Evidence:** the README says `make lint` runs "go vet (incl. the integration build tag)".
  `Makefile:47-49` runs only `go vet ./...` and `golangci-lint run ./...`. The tagged vets
  (`integration`, `acceptance`) exist only in `.github/workflows/ci.yml:25`.
- **Failure scenario:** a developer trusts `make lint` and only finds vet errors in tagged files
  in CI.
- **Verifier (confidence 9):** confirmed. There is no golangci config that adds build tags.

### CLAIM-3 · low · `CLAUDE.md:7`
- **Rule:** documentation must match the code.
- **Evidence:** "Two binaries share one codebase:" is followed by three bullets. `cmd/` has four
  binaries (`api`, `worker`, `mockprovider`, `healthcheck`), all built by the Dockerfile, and
  ADR-010 says four.
- **Failure scenario:** the project guidance contradicts itself about what the repository ships.
- **Verifier (confidence 8):** confirmed. The finding cited line 5; the sentence is on line 7.
